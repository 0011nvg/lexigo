# Облачные данные Lexi

Используется существующий проект Supabase `ajzfspevzlhsfduwrlzu`. Новый сервис или перенос аккаунтов не нужны.

## Что уже хранится в облаке

- `profiles`, `groups`, `group_members`: профили, группы и связь учителя с учениками.
- `custom_lessons`, `assignments`: созданные учителем уроки, их слова, переводы и задания.
- `sessions`, `word_progress`, `user_stats`: отправленные результаты, прогресс по словам и награды.
- `word_rounds`: пройденные слова внутри наборов.

Учебный словарь сайта версионируется в GitHub и загружается с сайта. Его не нужно копировать отдельно в каждый аккаунт.

## Включить дополнительные данные аккаунта

1. Открыть существующий проект в Supabase → SQL Editor → New query.
2. Вставить и выполнить целиком `supabase/migrations/20261106_account_state.sql`.
3. Обновить Lexi и войти в аккаунт. На главной появится подтверждение сохранения настроек после успешного ответа сервера.

Миграция добавляет только `account_state` и функцию её сохранения. Существующие таблицы и данные не удаляются. Повторный запуск допустим. Для новой установки сначала выполнить `supabase/schema.sql`, затем миграцию.

Дополнительно сохраняются выбранный класс, избранные модули, последнее открытое занятие, сложные слова, выбор слов для игр, настройки теста и печати, локальные отметки прохождения общих уроков и черновик нового урока учителя. Открытый редактор урока не заменяется данными с другого устройства: полученный черновик доступен при следующем открытии редактора.

Доступ к дополнительным данным есть только у владельца аккаунта. Они не влияют на подтверждённые сервером баллы и оценки. Прогресс, который учитель видит в кабинете, берётся из прежних таблиц с прежними правилами доступа.

Локальная копия остаётся для работы без сети; изменения отправляются при восстановлении связи, возвращении на страницу и каждые 30 секунд, пока она открыта. Не очищайте данные браузера до подтверждения отправки. Гостевые данные автоматически не присваиваются аккаунту; перенос гостевого прогресса доступен отдельно в профиле.

При первом подключении облачные настройки имеют приоритет над старой локальной копией. Новые изменения отправляются по отдельным ключам с проверкой версии; при одновременном редактировании одного и того же списка в двух устройствах действует последняя успешно сохранённая редакция списка.

## Проверка после включения

1. В аккаунте ученика выбрать класс и отметить сложное слово. Дождаться сообщения о сохранении.
2. Войти в тот же аккаунт на втором устройстве и проверить класс и список слов.
3. Завершить тренировку, затем проверить прогресс ученика в его профиле и кабинете учителя.
4. Создать урок учителя, сохранить и открыть его со второго устройства: сверить слова и переводы.
5. Без сети изменить настройки; вернуть связь и проверить их на втором устройстве.

До применения миграции новые настройки остаются локальными, а интерфейс сообщает, что требуется настройка сервера. Существующие сохранение уроков и отправка тренировок продолжают работать независимо.

Это синхронизация, а не резервное копирование базы. Политику резервных копий и восстановление нужно отдельно проверить в панели Supabase; данное обновление их не включает.
