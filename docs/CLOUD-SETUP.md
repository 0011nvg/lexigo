## 2. Почему Supabase (и почему не Firebase)

* **Supabase** — PostgreSQL + готовая авторизация + правила доступа на уровне строк (RLS). Связи «учитель → группа → ученик → задание → результат» естественно ложатся в реляционную базу, а права проверяет сама база, а не браузер.
* Бесплатного тарифа хватает для пилота.
* **Главное для России:** Supabase — открытое ПО. Его можно развернуть на сервере в РФ без изменения кода сайта (меняется только адрес в `config.js`). Firebase работает только в облаке Google за рубежом — это исключает его для реальных учеников из‑за требований о локализации (см. раздел 5).

## 3. Два режима запуска

**А. Тестовый пилот — Supabase Cloud (≈15 минут).** Только с тестовыми аккаунтами взрослых (вы, коллеги), без реальных данных детей.

**Б. Реальный запуск для учеников — Supabase на сервере в России.** Тот же `supabase/schema.sql`, тот же сайт. Нужен сервер у российского провайдера (Yandex Cloud, Selectel, VK Cloud, Timeweb Cloud и т. п.), домен и HTTPS. Это работа для системного администратора на 2–4 часа по официальной инструкции Supabase «Self-Hosting with Docker».

## 4. Пошагово: режим А (тестовый)

1. Зайдите на supabase.com → **New project**. Регион — Europe (Frankfurt). Придумайте пароль базы и сохраните его у себя (на сайт он не нужен).
2. **SQL Editor → New query** → вставьте целиком файл `supabase/schema.sql` из репозитория → **Run**. Должно появиться «Success».
3. **Authentication → URL Configuration:**
   * Site URL: `https://0011nvg.github.io/lexigo/`
   * Redirect URLs: добавьте `https://0011nvg.github.io/lexigo/auth.html` и `https://0011nvg.github.io/lexigo/auth.html?*`
4. **Authentication → Sign In / Providers → Email:** включено, **Confirm email** — включено, минимальная длина пароля — 8.
5. **Почта.** Встроенная почта Supabase предназначена только для проверки: письма уходят лишь адресам участников вашей команды Supabase и в очень малом количестве. Для учеников подключите свой SMTP: **Authentication → Emails → SMTP Settings** (например, почта Яндекс 360 или Mail.ru для домена). Там же переведите шаблоны писем на русский — тексты ниже.
6. **Project Settings → API:** скопируйте **Project URL** и ключ **anon public** (или **Publishable key**). Ключ **service_role / Secret** не копируйте никуда.
7. В GitHub откройте `config.js` → карандаш «Edit» → вставьте два значения → **Commit changes**. Через 1–2 минуты GitHub Pages обновит сайт.
8. Проверка: откройте сайт → «Войти» → зарегистрируйтесь учителем, создайте класс; в другом браузере (или режиме инкогнито) зарегистрируйтесь учеником по ссылке‑приглашению; назначьте задание и выполните его.

Шаблоны писем (Authentication → Emails → Templates):

* **Confirm signup** — тема «LEXIGO: подтвердите почту»; текст: «Привет! Чтобы закончить регистрацию в LEXIGO, нажмите ссылку: `{{ .ConfirmationURL }}`. Если вы не регистрировались — просто проигнорируйте письмо.»
* **Reset password** — тема «LEXIGO: новый пароль»; текст: «Чтобы задать новый пароль, нажмите ссылку: `{{ .ConfirmationURL }}`. Ссылка действует ограниченное время.»

## 5. Юридические и организационные вопросы — решить ДО регистрации реальных учеников

Я не юрист; ниже — перечень вопросов для консультации, а не юридическое заключение.

1. **Кто оператор персональных данных.** Вы как физлицо / самозанятая / ИП, или школа. От этого зависят реквизиты в документах и кто отвечает за обработку.
2. **Локализация (ч. 5 ст. 18 152‑ФЗ, в редакции 23‑ФЗ, с 1 июля 2025 г.).** Сбор и хранение ПДн граждан РФ с использованием баз данных за рубежом запрещены; штрафы для юрлиц — до 6 млн ₽, при повторе — до 18 млн ₽. Поэтому для реальных учеников нужен режим Б (сервер в РФ). Почтовый сервис для писем тоже лучше российский.
3. **Отдельное согласие на обработку ПДн (ч. 1 ст. 9 152‑ФЗ, в редакции 156‑ФЗ, с 1 сентября 2025 г.)** — оформляется отдельно от других документов. На сайте уже есть отдельный документ `consent.html` и отдельная галочка; текст нужно заполнить и проверить.
4. **Дети младше 14 лет:** согласие даёт родитель (законный представитель). Сейчас стоит галочка «мне есть 14 или родитель согласен» — для школы надёжнее собирать согласия родителей централизованно (через классного руководителя) или оставить регистрацию детей до 14 лет родителям.
5. **Уведомление Роскомнадзора** о начале обработки ПДн (ст. 22 152‑ФЗ) — уточнить, требуется ли в вашем случае.
6. **Политика конфиденциальности** опубликована на сайте (`privacy.html`) — заполнить реквизиты, место хранения, сроки ответа на запросы.
7. **Договор с хостинг‑провайдером** (поручение обработки) и уровень защищённости ИСПДн (ПП РФ № 1119).
8. **Порядок действий при утечке** (уведомление Роскомнадзора в установленные сроки).
9. **Если платформа используется в школе** — согласовать с администрацией и родителями.

## 5а. Рейтинг ТОП-3 (с 02.11.2026)

* Таблица `leaderboard` и функции `leaderboard_top / _preview / _claim` (миграция v2 уже применена к проекту).
* Отдельная таблица для каждой игры + урока (или набора слов задания) + числа слов в раунде; для финального теста — ещё набор слов и типы заданий, поэтому разные по сложности тесты не смешиваются.
* Места: больше верных ответов с первой попытки → меньше время → кто раньше. «Найди пару»: меньше время → меньше ошибок → кто раньше.
* Записаться можно только своей завершённой тренировкой, сохранённой сервером, не позже 2 часов; один игрок — одна строка (лучший результат). Таблицу видят все, включая гостей.
* Ограничение: ответы вычисляет браузер, сервер проверяет формат, режим, правдоподобие времени, уникальность и права. Подделать результат простым изменением данных в браузере нельзя, но технически подготовленный пользователь может отправить сфабрикованные ответы через API, как в любой браузерной игре. Учитель может попросить удалить строку — это делается в панели Supabase (Table Editor → leaderboard).

## 6. Как устроена безопасность

* Пароли — только в Supabase Auth (хеш bcrypt); сайт их не хранит.
* В публичных таблицах нет e‑mail; ученики не видят друг друга; учитель видит только учеников своих групп, другой учитель — никого.
* Роль нельзя поменять после регистрации; XP, серию, награды нельзя изменить напрямую — только функция `submit_session`, которая сама пересчитывает очки: не более 2 начислений за одно слово в день, миссии — не больше трёх в день, сундук и победа над стражем — один раз, страж проверяется по ответам на сервере, повтор одной и той же тренировки не начисляет ничего.
* На страницах входа и кабинета — Content Security Policy; все данные выводятся как текст (защита от XSS).
* Ключ в `config.js` публичный по замыслу; доступ ограничивают правила RLS.
