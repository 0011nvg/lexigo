# Безопасное внедрение облачных изменений LEXI

Этот документ описывает условия внедрения, а не подтверждает, что они уже выполнены. Состояние работающей базы, применённые миграции, наличие резервных копий, регион хранения и восстановление копии нужно отдельно проверить у владельца проекта. Не размещайте пароли, токены и строку подключения в репозитории или переписке.

## До применения

1. Определите действующий проект Supabase и регион хранения, доступ владельца и его план резервного копирования. Сверьте список таблиц, функций, политик RLS и фактически применённых миграций с файлами репозитория. Не используйте новый проект с реальными данными без отдельного согласования.
2. Сохраните согласованную резервную копию базы с данными и схемой, включая зависимости для авторизации, а также проверьте, какие дополнительные ресурсы (конфигурация Auth, Storage и секреты) она не содержит. Для восстановления учётных записей нужна проверенная процедура именно для используемого варианта Supabase: одна только выгрузка схемы приложения не подтверждает возможность восстановления Auth.
3. Восстановите копию в **изолированную тестовую среду** с надлежащей защитой и согласованным размещением данных; по возможности используйте обезличенные или синтетические данные. Сверьте контрольные суммы или количества ключевых записей, вход тестовых учётных записей, назначения и выполнение игр. Зафиксируйте время копии и результат проверки. При отсутствии проверенного восстановления остановите внедрение.
4. На изолированной базе, максимально соответствующей рабочей, выполните имеющиеся миграции и новые миграции в предусмотренном ими порядке, затем повторно выполните те миграции, которые объявлены безопасными для повторного запуска. Убедитесь, что миграции не переопределяют более новые функции из рабочей базы. Сохраните вывод и проверяйте ошибки, количество исходных и перенесённых событий по установленным правилам фильтрации, пропуски и дубликаты. Не удаляйте старые сессии.
5. Проверьте доступ ученика к собственным данным, отказ в доступе к чужим данным и запрет для гостя. Проверьте учителя своей и чужой группы и отзыв доступа после удаления участника. Наличие кода группы само по себе не подтверждает личность учителя, полномочия или согласие законного представителя. До предоставления новой расширенной аналитики определите и внедрите применимую модель подтверждения доступа; не считайте существующую проверку членства полноценным подтверждением.
6. Проверьте сохранение данных нескольких устройств, повторную отправку, разрыв соединения, восстановление очереди, заполнение локального хранилища, выход из учётной записи, удаление учётной записи и восстановление старых данных. Проверки на имитациях не заменяют испытаний с PostgreSQL и настоящим Supabase Auth/RLS.

## Внедрение и откат

Согласуйте окно работ, резервную копию, ответственного и точки контроля. Применяйте только проверенные миграции в соответствии с их отдельными инструкциями. Совместимость кода и схемы проверяется на тестовом окружении до публикации клиента. После применения проверьте работоспособность функций, RLS и контрольные количества; наблюдайте за ошибками и задержками синхронизации. Не сообщайте пользователям об успешном сохранении данных до подтверждения сервера.

При инциденте остановите дальнейшее внедрение и запись затронутой функции, сохраните журнал ошибки без секретов и персональных данных, верните совместимую версию клиента. Не удаляйте новые таблицы и не откатывайте схему вслепую: это может уничтожить накопленные после миграции результаты. Восстановление полной копии может затереть записи после момента резервирования; оператор должен предварительно оценить и сохранить изменения, выбрать точку восстановления и протестировать согласованность Auth и данных. Безопасный SQL-откат каждой миграции должен быть описан отдельно с учётом её конкретных зависимостей.

## Персональные данные

Обрабатывайте только данные, необходимые для обучения, ограничьте срок хранения и доступ, предусмотрите удаление учётной записи и связанных событий, включая резервные копии в рамках их политики хранения. Отдельно проверьте требования российского законодательства и договорные условия с квалифицированным юристом, в том числе локализацию первичной обработки и хранения персональных данных граждан РФ, допустимость трансграничной передачи, основания обработки и порядок получения согласий для несовершеннолетних. Расположение существующего проекта и юридическое соответствие этим документом не подтверждаются. Не переносите реальные данные в другой регион и не подключайте внешнего обработчика без отдельного согласования.
