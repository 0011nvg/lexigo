# LEXIGO: доступ для учителей, учеников и родителей

## Текущая версия
Статический сайт GitHub Pages. Словарь и игровые механики доступны без аккаунта. Прогресс сохраняется в localStorage конкретного браузера; это **не синхронизация** между устройствами. Отчёт CSV можно экспортировать вручную. Переключатель «Режим учителя» — изменение интерфейса, **не механизм защиты данных**.

## Предлагаемый путь: минимум трения
1. **Учитель** создаёт аккаунт по электронной почте и получает рабочий кабинет.
2. Учитель создаёт класс, назначает учебник и модули, создаёт для каждого ученика случайный код приглашения. Для ребёнка достаточно псевдонима и кода, без электронной почты и телефона. Код не должен содержать имя или дату рождения.
3. **Ученик** входит по коду класса и индивидуальному секретному коду; возвращается к занятиям с того же места на разных устройствах. Не хранить секрет в открытом виде на сервере.
4. **Родитель** получает отдельную пригласительную ссылку от учителя или школы для просмотра прогресса только своего ребёнка. На первом этапе родительский кабинет можно отложить: учитель передаёт сводку вручную.
5. **Учитель** видит только учеников своих классов, динамику по модулям, сложные слова, регулярность занятий и задания. Не показывать детские данные другим ученикам.

## Архитектура минимальной реализации
- GitHub Pages продолжает отдавать фронтенд; **авторизация и данные — на отдельном backend**.
- Подходящий стартовый вариант: Supabase (Auth, Postgres, Row Level Security) или эквивалентный управляемый сервис. Окончательный выбор после проверки стоимости, условий обработки данных детей, региона размещения и юридических требований.
- Сущности: teacher_profiles, classes, class_memberships, learner_profiles, assignments, word_attempts, word_review_state, guardian_links.
- На каждой таблице с детскими данными обязательны RLS/серверные правила: ученик — только свои записи, учитель — только назначенные классы, родитель — только подтверждённая связь с ребёнком.
- Записывать не только итоговую оценку, но и попытку: word_id, mode, correct_first_try, used_hint, retry, timestamp. Это позволит честно строить отчёты.
- Секреты backend и service-role keys никогда не добавлять в GitHub Pages или публичный репозиторий.

## Приватность и запуск
- Собирать минимально необходимое: псевдоним ребёнка, учебный прогресс, связь с классом. Не запрашивать дату рождения, адрес, фото или телефон ребёнка без необходимости.
- До запуска проверить применимые нормы защиты детских персональных данных и требования школы, согласия/основания обработки, сроки хранения, удаление данных и договор с провайдером.
- Встроить понятное удаление класса/ученика и экспорт результатов. Не использовать публичные рейтинги детей.
- Не выдавать простой UI-переключатель за авторизацию; серверная проверка доступа обязательна.
- Начать с пилота: один учитель, один класс, тестовые псевдонимы, затем постепенно расширять.

## Приёмочные сценарии
- Ученик с кодом A не видит данные ученика B.
- Учитель класса X не может получить данные класса Y через API.
- Родитель видит только подтверждённого ребёнка.
- Прогресс синхронизируется после выхода и входа на другом устройстве.
- При пропадании интернета тренировка не теряется: локальная очередь попыток и безопасная синхронизация после восстановления.
- Неверный/просроченный код не открывает доступ.
