# LEXIGO — локальная проверка игровых механик (этап 5)

## Как включить

Это **только изолированный демонстрационный режим** для вымышленных учителя, ученика и родителя. Запустите локальный Supabase CLI и Edge Function `learning-api`, затем в папке проекта выполните `python3 -m http.server 3000 --bind 127.0.0.1` и откройте `http://127.0.0.1:3000/?localDemo=1`.

На странице LEXIGO появится блок локальной серверной тренировки. Для запуска нужны JWT фиктивного ученика из **локального** Supabase Auth и UUID назначения, созданного фиктивным учителем. Токен хранится только в оперативной памяти вкладки, не в localStorage и не в URL. Вне локального адреса и без параметра `localDemo=1` адаптер не загружается. **Нельзя вводить production JWT или данные настоящих детей.**

## Серверные гарантии

- `next-question` выдаёт непредсказуемый серверный идентификатор раунда, привязанный к попытке и текущему индексу.
- `answer-question` проверяет текст, варианты quiz, truefalse, spelling, fix и audio по серверному ожидаемому ответу, не доверяя клиентскому `correct`.
- `play-round` обрабатывает многошаговые действия `pair`, `swap`, `answer`, `hint`, `retry`. Привязка JWT, серверная блокировка попытки, журнал идентификаторов запросов и отпечатки полезной нагрузки предотвращают повторное начисление одного действия и подмену роли.
- В `pairs` сервер хранит скрытые соответствия английских и русских плиток и список уже найденных пар.
- В `crystals` сервер хранит игровое поле 6×6, разрешает только соседние обмены, рассчитывает горизонтальные и вертикальные совпадения, падение и каскады, начисляет очки и после семи ходов открывает обязательное серверное задание со словом; только проверка этого ответа может дать отметку об освоении слова.
- В `boss` сервер хранит последовательность из трёх стадий (перевод, написание, верно/неверно), жизни, подсказку и обязательный переход через повторную попытку после ошибки.
- `cards` и `daily` остаются **самооценкой**, их события не помечаются как объективно проверенные.
- Прямые клиентские записи в игровые таблицы по-прежнему запрещены; ключ `service_role` остаётся только на сервере.

## Границы реализации

Тестовый серверный протокол использует упрощённые испытания в некоторых режимах: существующий режим Boss имеет дополнительные правила итогового теста, а `audio` воспроизводится через браузерный синтез речи, поэтому сервер не удостоверяет, что звук действительно был прослушан. Пары выдаются короткими раундами, а не всей длинной секцией сразу. Результаты локальной демонстрации не предназначены для официальных оценок и не должны автоматически смешиваться с историческими локальными достижениями.

В CI используются только вымышленные аккаунты, синтетические слова и локальные JWT. Отдельный тест `tests/verify.mjs` подтверждает неизменность **1035 исходных слов**, `tests/stage5-mobile.mjs` проверяет доступность демонстрационного интерфейса на телефоне и отсутствие включения без явного флага. Реальная защита от подсказок извне и списывания невозможна только средствами сервера.
