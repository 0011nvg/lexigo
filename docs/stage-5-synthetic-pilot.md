# LEXIGO — безопасный демонстрационный пилот (без реальных детей)

**Статус:** проектирование и автоматические проверки. Не разворачивать в production, не собирать персональные данные учащихся.

## Изолированный стенд

Запускать только Supabase CLI в локальном Docker / одноразовом GitHub Actions. Фиктивные аккаунты учителя, ученика, родителя и постороннего пользователя используют домен `example.invalid`. Supabase Auth выдаёт тестовые JWT; Edge Function проверяет их через `auth.getUser`, никогда не принимает actor ID от клиента. Service-role ключ доступен только серверному процессу, не браузеру.

## Матрица доступа

| Действие | Учитель класса | Ученик класса | Проверенный родитель | Посторонний |
|---|---|---|---|---|
| Создать задание | Да | Нет | Нет | Нет |
| Начать собственную попытку | Нет | Да | Нет | Нет |
| Отправить событие своей попытки | Нет | Да | Нет | Нет |
| Прочитать результаты ребёнка | Да | Только свои | После подтверждения | Нет |
| Выдать/отозвать приглашение | Да | Нет | Нет | Нет |
| Подтвердить/отозвать родительскую связь | Да, при отдельной проверке полномочий | Нет | Нет | Нет |
| Подтвердить/отозвать результат | Да, для завершённой попытки | Нет | Нет | Нет |

Всё перечисленное относится только к тестовым аккаунтам. Прямые INSERT/UPDATE/DELETE в задания и игровые события для `authenticated` запрещены. Запись идёт через проверенный Edge API и привилегированные RPC. RLS ограничивает чтение.

## Приглашения и отзыв

Одноразовый токен генерируется криптографически, в БД сохраняется SHA-256, исходный токен выдаётся только при создании. Проверять срок действия, роль, принадлежность к организации и отсутствие повторного использования; отозванный или истёкший токен не должен создавать связь. При отзыве зачисления прекращается доступ к заданиям и попыткам; при отзыве родительской связи прекращается доступ к результатам. Родительское приглашение **не подтверждает родство** — связь должен отдельно подтвердить уполномоченный учитель после проверки основания.

## Достоверность результатов

**Блокер:** сейчас клиент передаёт `correct`, поэтому может сфальсифицировать самооценку. Миграция `202610210007_unverified_game_scores.sql` вводит `verified_correct` и `verification_source`. Текущие события всегда остаются `client_unverified`, даже когда `correct=true`. До появления серверной проверки ответов нельзя показывать эти значения как проверенные достижения или использовать для официальных оценок. Серверный оценщик должен валидировать идентификатор слова, формат задания, правильный вариант/текст ответа, подсказки и режим игры; отдельные игровые режимы могут оставаться самооценкой.

## Условия перед пилотом с реальными пользователями

Нужны независимый аудит RLS и Edge API, серверная проверка оцениваемых ответов, возрастная модель регистрации и подтверждение законных оснований обработки данных детей, минимизация данных, ограничение хранения и удаление, журнал доступа, безопасное восстановление доступа, тесты на нагрузку и повторное воспроизведение событий, тестирование мобильных интерфейсов и процедура реагирования на инциденты. **Пока эти условия не выполнены, допускается только фиктивный локальный пилот.**

Все 1035 слов и игровые режимы остаются в неизменённых исходных файлах.
