# Письма LEXI на русском (Supabase Auth)

Письма о регистрации, восстановлении пароля и смене почты отправляет **Supabase Auth** — сайт LEXI их не отправляет и секретных ключей не хранит. Поэтому шаблоны меняются в панели Supabase. Готовые русские шаблоны лежат в этой папке:

| Файл | Шаблон в Supabase | Тема письма | Кнопка |
| --- | --- | --- | --- |
| `confirmation.html` | **Confirm signup** | Добро пожаловать в LEXI! Подтвердите электронную почту | Подтвердить электронную почту |
| `recovery.html` | **Reset password** | LEXI: восстановление пароля | Придумать новый пароль |
| `email_change.html` | **Change email address** | LEXI: подтвердите новый адрес почты | Подтвердить новый адрес |
| `magic_link.html` | **Magic link** | LEXI: ссылка для входа | Войти в LEXI |
| `invite.html` | **Invite user** | Вас пригласили в LEXI | Принять приглашение |
| `reauthentication.html` | **Reauthentication** | LEXI: код подтверждения | (код в письме) |

Темы — также в `subjects.json`. Шаблоны собираются из одного макета: `node supabase/email-templates/build.mjs` (правьте тексты там и пересоберите).

## Шаг 0. Почему письмо сейчас по-английски

С июня 2026 года на **бесплатном тарифе** новые проекты Supabase, которые отправляют письма встроенной почтой Supabase, **не могут менять шаблоны** — уходят стандартные английские. Кроме того, встроенная почта отправляет всего около 2 писем в час и только для тестов. Оба ограничения снимаются, когда подключён свой почтовый сервер (SMTP). Для учеников он нужен в любом случае.

## Шаг 1. Свой почтовый сервер (SMTP) — 10 минут

Подойдёт отдельный ящик на Яндексе или Mail.ru, например `lexi.platform@yandex.ru` (лучше не личный).

**Яндекс:** Яндекс ID → Безопасность → **Пароли приложений** → «Почта» → создать пароль. В настройках почты (Почтовые программы) включите доступ по протоколу IMAP/SMTP с паролями приложений.
**Mail.ru:** Настройки → Безопасность → **Пароли для внешних приложений** → создать.

В Supabase: **Authentication → Emails → SMTP Settings → Enable Custom SMTP**:

| Поле | Яндекс | Mail.ru |
| --- | --- | --- |
| Sender email | ваш ящик, например lexi.platform@yandex.ru | ваш ящик @mail.ru |
| Sender name | LEXI | LEXI |
| Host | smtp.yandex.ru | smtp.mail.ru |
| Port | 465 | 465 |
| Username | полный адрес ящика | полный адрес ящика |
| Password | пароль приложения (не основной пароль!) | пароль для внешнего приложения |

Сохраните. Адрес отправителя должен совпадать с ящиком, иначе почтовый сервис письмо не отправит. Пароль приложения хранится только в Supabase — в код сайта его не вставлять.

После этого в **Authentication → Rate Limits** поднимите «Rate limit for sending emails»: со своим SMTP по умолчанию 30 писем в час на весь проект. Рекомендуем **100 в час** — тогда класс из 25–30 учеников зарегистрируется на одном уроке, и останется запас на «Забыли пароль?».

**Сколько писем выдержит ящик.** Яндекс Почта через SMTP отправляет не больше **300 писем в сутки** с одного ящика (ограничение нельзя изменить; при подозрительных письмах может снизиться). Это примерно 250–300 регистраций или восстановлений пароля в день. Если учеников станет больше — второй вариант: сервис для служебных писем (например, Yandex Cloud Postbox), в Supabase меняются только поля SMTP.

## Шаг 2. Шаблоны

**Authentication → Emails → Templates.** Для каждого шаблона из таблицы:

1. Откройте шаблон (например, **Confirm signup**).
2. В **Subject** вставьте тему из таблицы.
3. В **Message body** перейдите на вкладку исходного кода (Source / HTML), удалите всё и вставьте **целиком** содержимое файла (например, `confirmation.html`). Удобнее всего открыть файл на GitHub → кнопка **Raw** → выделить всё → скопировать.
4. **Save changes**.

Переменные в двойных фигурных скобках (`{{ .ConfirmationURL }}`, `{{ .Email }}`, `{{ .Data.display_name }}`) не трогайте — их подставляет Supabase. Имя («Привет, Настя!») берётся из регистрации.

## Шаг 3. Адреса возврата (уже должны быть настроены)

**Authentication → URL Configuration:** Site URL `https://0011nvg.github.io/lexigo/`; Redirect URLs `https://0011nvg.github.io/lexigo/auth.html` и `https://0011nvg.github.io/lexigo/auth.html?*`. Без них ссылка из письма приведёт не на LEXI.

## Шаг 4. Проверка

1. Зарегистрируйтесь на https://0011nvg.github.io/lexigo/auth.html#signup с новым адресом.
2. Письмо «Добро пожаловать в LEXI! Подтвердите электронную почту» → кнопка «Подтвердить электронную почту».
3. На сайте: «Электронная почта успешно подтверждена! Теперь вы можете пользоваться LEXI» → «Продолжить».
4. Нажмите ту же ссылку ещё раз — «Ссылка больше не действует» и кнопка «Отправить письмо ещё раз» (не чаще раза в минуту).
5. «Забыли пароль?» → письмо «LEXI: восстановление пароля» → новый пароль.

Если письмо не пришло — проверьте «Спам» и **Authentication → Logs** (там видна ошибка SMTP, например неверный пароль приложения).

## Что сделано на сайте

Все экраны после ссылок из писем — на русском (`auth.js`): успешное подтверждение, смена адреса (в том числе «Почти готово!» после первой из двух ссылок), устаревшая или использованная ссылка, повторная отправка письма с паузой 60 секунд, «Почта ещё не подтверждена» при входе. Полная цепочка проверяется тестом `tests/e2e/email-flow.mjs` на локальном Supabase Auth с этими шаблонами и настоящей отправкой писем.
